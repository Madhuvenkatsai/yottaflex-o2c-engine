# Data Dictionary — Order-to-Cash Synthetic Ledger

## 1. Overview

This document describes the columns in the CSV files generated by the Order-to-Cash (O2C) synthetic data generator. Column names match the current generated CSV headers.

## 2. Accounts — `accounts.csv`

Represents customer or business accounts.

| Column | Description |
|---|---|
| `account_id` | Unique account identifier. |
| `legal_name` | Synthetic legal name assigned to the account. |
| `industry` | Industry category associated with the account. |
| `region` | Geographic region assigned to the account. |
| `currency` | Currency used for the account. |
| `credit_limit` | Credit limit configured for the account. |
| `account_status` | Current account status. |
| `opened_at` | Timestamp when the account was opened. |

## 3. Quotes — `quotes.csv`

Represents commercial quotations issued to accounts.

| Column | Description |
|---|---|
| `quote_id` | Unique quotation identifier. |
| `account_id` | Account associated with the quotation. |
| `motion` | Commercial motion or quotation category. |
| `quoted_amount` | Total quoted amount. |
| `currency` | Transaction currency. |
| `quote_status` | Current quotation status. |
| `issued_at` | Timestamp when the quotation was issued. |
| `expires_at` | Quotation expiry timestamp. |
| `decided_at` | Timestamp when a quotation decision was recorded. |

## 4. Quote Lines — `quote_lines.csv`

Contains individual line items belonging to quotations.

| Column | Description |
|---|---|
| `quote_line_id` | Unique quotation line identifier. |
| `quote_id` | Parent quotation identifier. |
| `line_number` | Line sequence within the quotation. |
| `description` | Description of the quoted item. |
| `quantity` | Quantity quoted. |
| `unit_price` | Price per unit. |
| `line_amount` | Total amount for the line. |
| `currency` | Currency for the line item. |

## 5. Sales Orders — `sales_orders.csv`

Represents orders created from accepted quotations.

| Column | Description |
|---|---|
| `sales_order_id` | Unique sales order identifier. |
| `quote_id` | Source quotation identifier. |
| `account_id` | Account placing the order. |
| `order_amount` | Total order amount. |
| `currency` | Transaction currency. |
| `order_status` | Current order status. |
| `booked_at` | Timestamp when the order was booked. |
| `closed_at` | Timestamp when the order was closed, if applicable. |

## 6. Order Lines — `order_lines.csv`

Contains individual line items belonging to sales orders.

| Column | Description |
|---|---|
| `order_line_id` | Unique order line identifier. |
| `sales_order_id` | Parent sales order identifier. |
| `quote_line_id` | Source quotation line identifier. |
| `line_number` | Line sequence within the order. |
| `description` | Description of the ordered item. |
| `quantity` | Ordered quantity. |
| `unit_price` | Unit price. |
| `line_amount` | Total amount for the line. |
| `currency` | Currency for the line item. |

## 7. Shipments — `shipments.csv`

Represents fulfillment activity against sales orders.

| Column | Description |
|---|---|
| `shipment_id` | Unique shipment identifier. |
| `sales_order_id` | Sales order associated with the shipment. |
| `account_id` | Account associated with the shipment. |
| `fulfilled_amount` | Amount fulfilled by the shipment. |
| `shipment_status` | Current shipment status. |
| `packed_at` | Timestamp when the shipment was packed. |
| `shipped_at` | Timestamp when the shipment was dispatched. |
| `delivered_at` | Timestamp when the shipment was delivered. |

## 8. Invoices — `invoices.csv`

Represents invoices issued for sales orders.

| Column | Description |
|---|---|
| `invoice_id` | Unique invoice identifier. |
| `sales_order_id` | Related sales order identifier. |
| `shipment_id` | Related shipment identifier, when present. |
| `account_id` | Account billed. |
| `invoice_amount` | Invoice amount before tax. |
| `tax_amount` | Tax amount. |
| `total_due` | Total invoice amount including tax. |
| `balance_due` | Outstanding invoice balance. |
| `currency` | Invoice currency. |
| `invoice_status` | Current invoice status. |
| `issued_at` | Invoice issue timestamp. |
| `due_at` | Invoice payment due timestamp. |

## 9. Invoice Lines — `invoice_lines.csv`

Contains individual line items belonging to invoices.

| Column | Description |
|---|---|
| `invoice_line_id` | Unique invoice line identifier. |
| `invoice_id` | Parent invoice identifier. |
| `sales_order_id` | Related sales order identifier. |
| `order_line_id` | Related sales order line identifier. |
| `shipment_id` | Related shipment identifier, when present. |
| `line_number` | Line sequence within the invoice. |
| `description` | Description of the invoiced item. |
| `quantity` | Invoiced quantity. |
| `line_amount` | Total amount for the invoice line. |
| `currency` | Currency for the line item. |

## 10. Payments — `payments.csv`

Represents payments received from accounts.

| Column | Description |
|---|---|
| `payment_id` | Unique payment identifier. |
| `account_id` | Account that made the payment. |
| `instrument` | Payment instrument or method. |
| `payment_amount` | Total payment amount received. |
| `unapplied_amount` | Payment amount not allocated to invoices. |
| `payment_status` | Current payment status. |
| `posted_at` | Timestamp when the payment was posted. |

## 11. Payment Allocations — `payment_allocations.csv`

Records allocations of payments to invoices. A payment may be allocated across invoices, and an invoice may receive allocations from multiple payments, subject to the implemented business rules.

| Column | Description |
|---|---|
| `payment_id` | Payment identifier. |
| `invoice_id` | Invoice receiving the payment allocation. |
| `allocated_amount` | Amount allocated to the invoice. |
| `allocated_at` | Timestamp when the allocation was recorded. |

The current CSV header does not include a separate allocation identifier.

## 12. Disputes — `disputes.csv`

Represents invoice-related disputes.

| Column | Description |
|---|---|
| `dispute_id` | Unique dispute identifier. |
| `invoice_id` | Invoice under dispute. |
| `account_id` | Account associated with the dispute. |
| `dispute_amount` | Amount being disputed. |
| `reason_code` | Dispute reason category. |
| `dispute_status` | Current dispute status. |
| `opened_at` | Timestamp when the dispute was opened. |

## 13. Status Events — `status_events.csv`

Provides event history for entity status changes.

| Column | Description |
|---|---|
| `event_id` | Unique event identifier. |
| `entity_type` | Type of entity associated with the event. |
| `entity_id` | Identifier of the affected entity. |
| `from_status` | Status before the event. |
| `to_status` | Status after the event. |
| `occurred_at` | Timestamp when the event occurred. |

## 14. Ground Truth — `ground_truth.csv`

Stores labels for injected anomalies. This file is intended to remain separate from the ordinary business entity tables.

| Column | Description |
|---|---|
| `truth_id` | Unique ground-truth record identifier. |
| `anomaly_code` | Code identifying the anomaly category. |
| `severity` | Severity assigned to the anomaly. |
| `anchor_table` | Table containing the primary entity associated with the anomaly. |
| `anchor_id` | Identifier of the primary entity associated with the anomaly. |
| `related_ids` | Identifiers of related entities. |
| `notes` | Explanation or context for the anomaly. |
| `label_only` | Indicator associated with the ground-truth label. |

## 15. Checksum Manifest — `checksum_manifest.csv`

Provides integrity and reproducibility metadata for generated files.

| Column | Description |
|---|---|
| `file` | Name of the file being tracked. |
| `row_count` | Number of data rows recorded for the file. |
| `sha256` | SHA-256 checksum recorded for the file. |

## 16. Verification Report — `verification_report.csv`

Contains results from the generator's implemented validation checks.

| Column | Description |
|---|---|
| `check` | Name of the validation check. |
| `passed` | Whether the check passed. |
| `detail` | Additional information about the result. |

## 17. Key Relationships

- `quotes.account_id` → `accounts.account_id`
- `quote_lines.quote_id` → `quotes.quote_id`
- `sales_orders.quote_id` → `quotes.quote_id`
- `sales_orders.account_id` → `accounts.account_id`
- `order_lines.sales_order_id` → `sales_orders.sales_order_id`
- `order_lines.quote_line_id` → `quote_lines.quote_line_id`
- `shipments.sales_order_id` → `sales_orders.sales_order_id`
- `invoices.sales_order_id` → `sales_orders.sales_order_id`
- `invoices.shipment_id` → `shipments.shipment_id`, when present
- `invoice_lines.invoice_id` → `invoices.invoice_id`
- `invoice_lines.order_line_id` → `order_lines.order_line_id`, when present
- `payments.account_id` → `accounts.account_id`
- `payment_allocations.payment_id` → `payments.payment_id`
- `payment_allocations.invoice_id` → `invoices.invoice_id`
- `disputes.invoice_id` → `invoices.invoice_id`
- `disputes.account_id` → `accounts.account_id`

`status_events` associates events with entities through `entity_type` and `entity_id`. These polymorphic references require validation against the appropriate entity table.

The exact nullability, enum values, uniqueness constraints, and foreign-key enforcement rules are defined by the implementation and should be verified against the generated data and validation code.
