# Data Dictionary — Order-to-Cash Synthetic Ledger

## 1. Overview

This document describes the columns in the CSV files generated by the Order-to-Cash (O2C) synthetic data generator. Column names match the generated CSV headers. Monetary values are decimal strings with exactly two fractional digits. Timestamps are UTC strings in ISO 8601 form. Empty optional values are written as empty CSV fields and as SQL `NULL`.

## 2. Accounts — `accounts.csv`

Represents customer or business accounts.

| Column | Description |
|---|---|
| `account_id` | Unique account identifier. |
| `legal_name` | Synthetic legal name assigned to the account. |
| `industry` | Industry category associated with the account. |
| `region` | Geographic region assigned to the account. |
| `currency` | Currency used for the account. |
| `credit_limit` | Credit limit configured for the account. |
| `account_status` | Current account status. |
| `opened_at` | Timestamp when the account was opened. |

## 3. Quotes — `quotes.csv`

Represents commercial quotations issued to accounts.

| Column | Description |
|---|---|
| `quote_id` | Unique quotation identifier. |
| `account_id` | Account associated with the quotation. |
| `motion` | Commercial motion or quotation category. |
| `quoted_amount` | Total quoted amount. |
| `currency` | Transaction currency. |
| `quote_status` | Current quotation status. |
| `issued_at` | Timestamp when the quotation was issued. |
| `expires_at` | Quotation expiry timestamp. |
| `decided_at` | Timestamp when a quotation decision was recorded. |

## 4. Quote Lines — `quote_lines.csv`

Contains individual line items belonging to quotations.

| Column | Description |
|---|---|
| `quote_line_id` | Unique quotation line identifier. |
| `quote_id` | Parent quotation identifier. |
| `line_number` | Line sequence within the quotation. |
| `description` | Description of the quoted item. |
| `quantity` | Quantity quoted. |
| `unit_price` | Price per unit. |
| `line_amount` | Total amount for the line. |
| `currency` | Currency for the line item. |

## 5. Sales Orders — `sales_orders.csv`

## 11. Payment Allocations — `payment_allocations.csv`

| Column | Description |

| `invoice_id` | Invoice receiving the payment allocation. |
| `allocated_amount` | Amount allocated to the invoice. |
| `allocated_at` | Timestamp when the allocation was recorded. |

The current CSV header does not include a separate allocation identifier.

## 14. Ground Truth — `ground_truth.csv`

Stores labels for injected anomalies. This file is intended to remain separate from the ordinary business entity tables.

| Column | Description |
|---|---|
| `truth_id` | Unique ground-truth record identifier. |
| `anomaly_code` | Code identifying the anomaly category. |
| `severity` | Severity assigned to the anomaly. |

| `anchor_id` | Identifier of the primary entity associated with the anomaly. |
| `related_ids` | Identifiers of related entities. |
| `notes` | Explanation or context for the anomaly. |
| `label_only` | Indicator associated with the ground-truth label. |

| Column | Description |
|---|---|

## 17. Key Relationships

- `quotes.account_id` → `accounts.account_id`
- `quote_lines.quote_id` → `quotes.quote_id`
- `sales_orders.quote_id` → `quotes.quote_id`
- `sales_orders.account_id` → `accounts.account_id`
- `order_lines.sales_order_id` → `sales_orders.sales_order_id`
- `order_lines.quote_line_id` → `quote_lines.quote_line_id`
- `shipments.sales_order_id` → `sales_orders.sales_order_id`
- `invoices.sales_order_id` → `sales_orders.sales_order_id`
- `invoices.shipment_id` → `shipments.shipment_id`, when present
- `invoice_lines.invoice_id` → `invoices.invoice_id`
- `invoice_lines.order_line_id` → `order_lines.order_line_id`, when present
- `payments.account_id` → `accounts.account_id`
- `payment_allocations.payment_id` → `payments.payment_id`
- `payment_allocations.invoice_id` → `invoices.invoice_id`
- `disputes.account_id` → `accounts.account_id`

`disputes.invoice_id` normally refers to an invoice, but one deliberately injected scenario points to a nonexistent invoice. The reference is detected by the auditor and intentionally has no SQLite foreign-key constraint.

`status_events` associates events with entities through `entity_type` and `entity_id`; supported entity types are `account`, `quote`, `sales_order`, `shipment`, `invoice`, `payment`, and `dispute`. The reference is validated against the corresponding entity table.

## 18. Keys, optional fields, and states

Generated primary keys are:

| Table | Primary key |
|---|---|
| `accounts` | `account_id` |
| `quotes` | `quote_id` |
| `quote_lines` | `quote_line_id` |
| `sales_orders` | `sales_order_id` |
| `order_lines` | `order_line_id` |
| `shipments` | `shipment_id` |
| `invoices` | `invoice_id` |
| `invoice_lines` | `invoice_line_id` |
| `payments` | `payment_id` |
| `payment_allocations` | (`payment_id`, `invoice_id`) |
| `disputes` | `dispute_id` |
| `status_events` | `event_id` |
| `ground_truth` | `truth_id` |

Document IDs use a type-specific prefix, four-digit fiscal year, and six-digit sequence. Line IDs use `QTL`, `OTL`, and `ITL` prefixes. Ground-truth IDs use the `GT-` prefix.

`sales_orders.closed_at` is empty when an order is not closed. `invoices.shipment_id`, `invoice_lines.order_line_id`, and `invoice_lines.shipment_id` are treated as nullable references by the verifier and SQLite export; the fixed-seed generator populates them for every generated invoice and invoice line. All other generated entity and line references are populated, except for the single injected missing `disputes.invoice_id`.

Current entity-state values are:

| Field | Values |
|---|---|
| `account_status` | `active`, `on_hold` |
| `quote_status` | `accepted`, `expired`, `rejected` |
| `order_status` | `booked`, `in_fulfillment`, `fulfilled`, `closed` |
| `shipment_status` | `delivered` |
| `invoice_status` | `open`, `partial`, `paid`, `disputed` |
| `payment_status` | `allocated` |
| `dispute_status` | `under_review` |

The generated event transitions are `prospect -> active` for accounts; `draft -> sent` and `sent -> accepted/expired/rejected` for quotes; `none -> booked -> in_fulfillment -> fulfilled -> closed` for sales orders; `shipped -> delivered` for shipments; `draft -> open/partial/paid/disputed` for invoices; `received -> allocated` for payments; and `none -> under_review` for disputes. One sales-order event intentionally skips from `booked` to `closed`.

## 19. Implemented validation

`verification_report.csv` records observed counts and evidence for:

- Configured volumes and derived line/allocation counts.
- Primary-key uniqueness and nonempty keys, ID formats, and monetary string formats.
- Declared foreign keys, polymorphic event references, and cross-entity account/order consistency.
- Entity status values, allowed event transitions, and timestamp chronology.
- Positive line and invoice amounts, line extensions, invoice line totals, invoice tax and total due, invoice balance bounds, and status/balance consistency.
- Invoice allocation reconciliation to balances, payment reconciliation to allocations plus unapplied amounts, duplicate allocation pairs, and over-allocation of invoice totals.
- Independent detection of all five injected scenarios followed by comparison with their ground-truth anchor IDs.
- Ground-truth schema and separation from operational tables.

The auditor does not treat the expected label as evidence of detection. Each detector reports its observed IDs; the evaluation check separately compares them with the ground-truth IDs. The injected payment allocation can make one invoice's allocation total diverge from its recorded balance and can exceed one payment's amount; these specific observed discrepancies are reported and evaluated as part of that scenario.

The fixed challenge configuration targets 6,934 payment rows, 8,000 invoices, and 420 disputes. Insufficient eligible settlement or dispute records raise a generation error instead of silently reducing the target. An order is ordinarily closed only when it is fulfilled and all its invoices have a zero balance; the injected closed-with-unpaid scenario is the single intentional exception.
